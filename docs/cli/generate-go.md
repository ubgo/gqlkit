# Generate a Go SDK from the command line

`gqlkit generate` reads a GraphQL schema in SDL and writes a typed Go client SDK: one builder per query and mutation, one Go type per GraphQL type, and its own HTTP client and batching packages. Use it when you want a Go client for a GraphQL API and you have (or can fetch) its schema. If you would rather drive the generator from a Go program, see [Run the generators from Go code](./programmatic.md).

The runnable version of this page is [`example-cli/generate-go.sh`](../../example-cli/generate-go.sh). It builds the CLIs from this repository, generates into a fresh module, builds the result and calls the API through it.

## Before you start

- Go installed, and a Go module to generate into (a directory with a `go.mod`).
- The `gqlkit` binary. Install it with `go install github.com/ubgo/gqlkit/gqlkit/cmd/gqlkit@latest`, or see the [README install section](../../README.md#install) for release archives.
- A schema in SDL (`.graphql`). If you only have a live endpoint, fetch one first with [`gqlkit-sdl fetch`](./fetch-schema.md). An introspection JSON file does not work: `gqlkit` reads SDL only (see [Where the schema comes from](../choosing/schema-source.md)).

## Step 1: Create or pick the module

The generated packages import each other by their full import path, so gqlkit has to know where in your module the SDK will live.

```sh
go mod init example.com/cliapp
```

## Step 2: Get the schema

```sh
gqlkit-sdl fetch --url "$GRAPHQL_URL" -o schema.graphql
```

Any SDL file works here; it does not have to come from `gqlkit-sdl`.

## Step 3: Generate

```sh
gqlkit generate \
	-s schema.graphql \
	-o ./sdk \
	-m "$(go list -m)/sdk" \
	-c "$EXAMPLE_DIR/go.config.jsonc"
```

`$EXAMPLE_DIR/go.config.jsonc` is the example's [config file](../../example-cli/go.config.jsonc); in your project it is usually just `-c config.jsonc`, and you can leave `-c` out if you have no custom scalars to bind.

What each flag does:

| Flag | Default | Meaning |
| --- | --- | --- |
| `-s`, `--schema` | none, required | SDL file to read. Also accepts a glob such as `'./schema/*.graphql'` or `'./schema/**/*.graphql'` (quote it; an unquoted glob is an error). |
| `-o`, `--output` | `./sdk` | Directory to write. Created if missing. Existing files are overwritten; nothing is deleted unless you pass `--prune`. |
| `-m`, `--module` | empty | Import path of the output directory, used in the generated `import` lines. |
| `-p`, `--package` | `sdk` | A name printed in the progress output. If the value contains a `/`, it is used as the import path instead, like `-m`. |
| `-c`, `--config` | empty | `config.jsonc` with scalar bindings and input options. See [config.jsonc](./config.md). A path that does not exist is an error. |
| `--prune` | off | After generating, delete files in `-o` that start with the `// Code generated by gqlkit. DO NOT EDIT.` banner but were not written by this run, then remove subdirectories that left empty. Files without the banner are never touched. |
| `--dry-run` | off | With `--prune` only: print `Would prune: ...` instead of deleting. The SDK files are still written. |

### Which import-path flag to pass

The import path must be the path of the output directory, not the path of your module. For module `example.com/cliapp` and `-o ./sdk`, that is `example.com/cliapp/sdk`. gqlkit picks the import path in this order (from `Config.Validate` in [`gqlkit/pkg/clientgen/config.go`](../../gqlkit/pkg/clientgen/config.go)):

| You pass | Import path used | When to use it |
| --- | --- | --- |
| `-m example.com/cliapp/sdk` | `example.com/cliapp/sdk` | Always safe. Scripts and CI. `-m "$(go list -m)/sdk"` derives it. |
| `-p example.com/cliapp/sdk` (no `-m`) | `example.com/cliapp/sdk` | Same result as `-m`; kept for older scripts. `-m` wins if both are set. |
| neither, inside a module | the module path plus the output directory's path inside the module | Quick local runs. gqlkit finds the nearest `go.mod` in the current directory or a parent. `-o ./internal/gql` from the module root gives `example.com/cliapp/internal/gql`; `-o ./gql` from `example.com/cliapp`'s `sub/` directory gives `example.com/cliapp/sub/gql`. |
| neither, no `go.mod` here or above | none: an error | `cannot determine the generated SDK's import path: pass --module (-m), or run inside a Go module that contains the output directory: no go.mod found in <dir> or any parent directory` |

## Step 4: Use it

The SDK has no runtime dependency on gqlkit, so `go.mod` gains no `require` line for it. Only a binding to a third-party type (for example `github.com/google/uuid.UUID`) needs a `go get` for that package.

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"
	"time"

	"example.com/cliapp/sdk/fields"
	"example.com/cliapp/sdk/graphqlclient"
	"example.com/cliapp/sdk/inputs"
	"example.com/cliapp/sdk/queries"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	client := graphqlclient.NewClient(os.Getenv("GRAPHQL_URL"))
	qr := queries.NewQueryRoot(client)

	pong, err := qr.Ping().Execute(ctx)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("ping:", pong)

	todos, err := qr.Todos().
		Pagination(&inputs.PaginationInput{Limit: 2}).
		Select(func(t *fields.TodoFields) {
			t.ID().Text().CreatedAt()
		}).
		Execute(ctx)
	if err != nil {
		log.Fatal(err)
	}
	for _, t := range todos {
		// CreatedAt is a time.Time because go.config.jsonc binds DateTime.
		fmt.Printf("todo %s: %q created %s\n", t.ID, t.Text, t.CreatedAt.Format(time.DateOnly))
	}
}
```

## Step 5: Regenerate with --prune

When the schema changes, run the same command with `--prune`. It deletes generated files the new schema no longer produces and leaves anything you wrote by hand alone, because only files that start with the `// Code generated by gqlkit. DO NOT EDIT.` banner are candidates. Add `--dry-run` first to see the list:

```sh
gqlkit generate -s schema.graphql -o ./sdk -m "$(go list -m)/sdk" -c config.jsonc --prune --dry-run
```

Real output from `example-cli/out/go-app`, after planting a stale `queries/query_removed.go` and an `old/old.go` with the banner, and a hand-written `queries/helpers.go` without it (progress lines omitted):

```
Would prune: old/
Would prune: old/old.go
Would prune: queries/query_removed.go
SDK generated successfully in ./sdk
```

Without `--dry-run` the same run prints `Pruned: ...` for the same three entries, removes the emptied `old/` directory, and keeps `helpers.go`. [`example-cli/test.sh`](../../example-cli/test.sh) checks exactly that.

## Pitfalls

- **`-m` set to the module path alone.** `-m "$(go list -m)"` with `-o ./sdk` makes the SDK import `example.com/cliapp/types` instead of `example.com/cliapp/sdk/types`, and `go build` fails with `no required module provides package example.com/cliapp/builder`. Add the output directory: `-m "$(go list -m)/sdk"`.
- **Auto-detection follows the directory you run from.** Without `-m`, the import path is computed from the nearest `go.mod` and where `-o` sits inside that module, so the same command run from two directories writes two different import paths. Scripts should pass `-m`.
- **Stale files after a schema change.** Without `--prune` the generator overwrites the files it writes but deletes nothing, so a removed operation leaves its old `queries/query_x.go` behind, which then fails to compile against the new `types`. Regenerate with `--prune` (see [Step 5](#step-5-regenerate-with---prune)).
- **`--dry-run` still generates.** It only skips the deletions; the SDK files are written as usual. Use it to see what `--prune` would remove, not as a no-op preview of the whole run.
- **`-p` does not rename packages.** Each generated directory has its own package name (`queries`, `types`, `fields`, ...). A `-p` value without a slash only changes the `Package name:` line in the output.
- **An error prints the usage text after it.** On failure both CLIs print `Error: ...` followed by the full flag list. The first line is the reason; the rest is not a second error.
- **Unexpected `any` fields.** A custom scalar with no binding and no built-in mapping becomes `any`. See [config.jsonc](./config.md).
- **An unquoted glob.** The shell expands `-s ./schema/*.graphql` into several arguments, and gqlkit stops with `Error: unexpected argument(s): ./schema/user.graphql` and `hint: if you passed a glob to -s, quote it so the shell does not expand it, e.g. -s './schema/*.graphql'`.
