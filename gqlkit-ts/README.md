# gqlkit-ts

A lightweight, zero-dependency TypeScript runtime library for executing GraphQL queries. Provides a typed HTTP client, error handling, batching and the builder primitives that SDKs generated by [`gqlkit generate-ts`](https://github.com/ubgo/gqlkit/blob/main/docs/cli/generate-ts.md) are built on.

Most apps use it in two places only: they construct a `GraphQLClient` and pass it to the generated `QueryRoot` / `MutationRoot`, and they import `batch` and the error classes. Everything else in a generated SDK (the builders, field selectors and result types) is generated code that imports this package. It also works on its own as a small typed GraphQL client for hand-written documents.

- Guides: [client options](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/client.md), [errors](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/errors.md), [batching](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/batching.md), [low-level API](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/low-level.md), and the full [documentation index](https://github.com/ubgo/gqlkit/blob/main/docs/README.md).
- Runnable samples for every guide: [`example-ts/cmd/samples`](https://github.com/ubgo/gqlkit/tree/main/example-ts/cmd/samples).
- Release history: [CHANGELOG](./CHANGELOG.md).

## Installation

```bash
npm install gqlkit-ts
```

## Quick Start

```typescript
import { GraphQLClient } from "gqlkit-ts";

const client = new GraphQLClient("https://api.example.com/graphql");

const data = await client.execute<{ users: { id: string; name: string }[] }>(
  `query { users { id name } }`
);

console.log(data.users);
```

## With a generated SDK

Generate the SDK once (`gqlkit generate-ts -s schema.graphql -o ./src/sdk`), then build the client and hand it to the generated roots:

```typescript
import { GraphQLClient, GraphQLErrors, batch } from "gqlkit-ts";
import { QueryRoot } from "./sdk/queries";

const client = new GraphQLClient("https://api.example.com/graphql", { authToken: token });
const qr = new QueryRoot(client);

// One operation: the result type is narrowed to the selected fields.
const todos = await qr.todos().select((t) => t.id().text()).execute();

// Several operations in one request, typed per alias.
const { open, done } = await batch(client, {
  open: qr.todos().filter({ done: false }).select((t) => t.id()),
  done: qr.todos().filter({ done: true }).select((t) => t.id()),
});
```

Selecting fields, arguments, scalars and unions are covered in the [TypeScript guides](https://github.com/ubgo/gqlkit/blob/main/docs/README.md#typescript-guides).

## Usage

### Creating a Client

```typescript
import { GraphQLClient } from "gqlkit-ts";

const client = new GraphQLClient("https://api.example.com/graphql", {
  authToken: "your-token",             // Sets Authorization: Bearer header
  headers: { "X-Custom": "value" },    // Additional headers
  fetch: customFetch,                  // Custom fetch implementation (optional)
});
```

### Typed Queries

```typescript
interface UsersResponse {
  users: { id: string; name: string; email: string }[];
}

const data = await client.execute<UsersResponse>(
  `query GetUsers($limit: Int!) { users(limit: $limit) { id name email } }`,
  { limit: 10 }
);

// data.users is fully typed
```

### Raw Queries

```typescript
const data = await client.rawQuery(
  `query { users { id name } }`
);
// Returns unknown — useful for ad-hoc/untyped queries
```

### Batching Multiple Queries Into One Request

Use `batch` to send several builders as a single GraphQL operation with aliases — one HTTP round trip, not N. All builders must share the same operation type (all queries or all mutations).

```typescript
import { batch } from "gqlkit-ts";

const { open, completed } = await batch(client, {
  open: qr.tasks(),
  completed: qr.tasks().status("completed"),
});
// → POST /graphql once
// query Batch($completed_status: Status) {
//   open: tasks { ... }
//   completed: tasks(status: $completed_status) { ... }
// }
```

The result is keyed by the alias you supplied; each value is typed from that builder's `execute()` return type. Argument names are namespaced with the alias (`$completed_status`), so two builders sharing an argument name don't collide.

Aliases and the operation name must be valid GraphQL names (`/^[_A-Za-z][_0-9A-Za-z]*$/`); anything else is rejected before a request is sent. Root fields go out in the order of the object you pass, which for mutations is also the order the server runs them in.

If one alias fails, `batch` rejects with `GraphQLErrors`; the aliases that resolved are on `err.data`, and each error's `path[0]` names the failing alias.

Pass `{ opName }` to override the default `Batch` operation name:

```typescript
await batch(client, { ... }, { opName: "DashboardLoad" });
```

### Error Handling

```typescript
import { GraphQLClient, GraphQLErrors, GraphQLHTTPError } from "gqlkit-ts";

try {
  const data = await client.execute(query);
} catch (err) {
  if (err instanceof GraphQLErrors) {
    // The server answered with GraphQL errors
    for (const e of err.errors) {
      console.error(e.message);       // Error description
      console.error(e.locations);     // Source locations in the query
      console.error(e.path);          // Response field path
      console.error(e.extensions);    // Vendor-specific metadata
    }
    console.log(err.data);            // Partial data returned alongside the errors, if any
  } else if (err instanceof GraphQLHTTPError) {
    // The response was not a GraphQL response (e.g. an HTML 502 page)
    console.error(err.status, err.body);
  }
  // Network failures and aborts are rethrown unchanged from fetch
}
```

### Cancelling a Request

`execute`, `rawQuery` and `batch` take an optional `signal`, and so do the `execute()` and `executeRaw()` of a builder in a generated SDK (`qr.todos().select(...).execute({ signal })`):

```typescript
const controller = new AbortController();
const pending = client.execute(query, variables, { signal: controller.signal });
// also: client.rawQuery(query, variables, { signal }) and batch(client, { ... }, { signal })
controller.abort(); // pending rejects with the signal's reason (an AbortError by default)
```

A signal that is already aborted rejects before anything is sent. The rejection is the signal's own reason, unwrapped, so `err.name === "AbortError"` checks and custom `controller.abort(reason)` values both work. One signal can cancel several calls. There is still no built-in timeout: for a deadline pass `{ signal: AbortSignal.timeout(ms) }`, and a call that runs out of time rejects with a `TimeoutError`.

To give every request through a client the same deadline instead, wrap `fetch` in the client options (see [client: timeouts](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/client.md#step-3--add-a-timeout-to-every-request)). Builders in SDKs generated by older gqlkit releases take no signal; regenerate to get it.

### Custom Scalar Codecs

When a scalar binding in `config.jsonc` sets `decode` / `encode` (for example a luxon `DateTime`), the generated SDK passes those functions to the runtime: response values are decoded before `execute()` returns them (including inside lists, nested objects, aliases, union and interface fragments, and `batch()` results), and argument values are encoded before variables are sent. `executeRaw()` always returns the undecoded wire values. A codec that throws surfaces as `ScalarCodecError`, whose `path` names the failing value (`todos.0.createdAt`, or `$filter.createdAfter` for variables). Fragment decoding needs `__typename` in the response, which the generator selects for you. Without codecs configured, nothing changes.

## API Reference

### `GraphQLClient`

HTTP client for executing GraphQL operations.

| Method | Description |
|---|---|
| `execute<T>(query, variables?, request?)` | Execute a query and return typed `data`; `request` is `RequestOptions` (`{ signal?: AbortSignal }`) |
| `rawQuery(query, variables?, request?)` | Execute a query and return untyped `data`; same `request` |

### `batch(client, builders, options?)`

Merges multiple builders into a single GraphQL operation. Returns an alias-keyed result object, each value typed from the corresponding builder's `execute()` return type.

| Argument | Type | Description |
|---|---|---|
| `client` | `GraphQLClient` | Client used to send the merged operation |
| `builders` | `Record<string, BatchableBuilder>` | Alias → builder map; aliases become GraphQL response keys |
| `options.opName` | `string` | Operation name (default: `"Batch"`) |
| `options.signal` | `AbortSignal` | Cancels the merged request |

Throws before sending if the input is empty, if builders mix `query` and `mutation`, if an alias or the operation name is not a valid GraphQL name, or if two aliases would produce the same namespaced variable (alias `a` + argument `b_c` and alias `a_b` + argument `c`).

### `ClientOptions`

| Option | Type | Description |
|---|---|---|
| `headers` | `Record<string, string>` | Additional HTTP headers for every request; names are case-insensitive and replace the defaults |
| `authToken` | `string` | Bearer token for the `Authorization` header; wins over an `Authorization` entry in `headers` |
| `fetch` | `typeof fetch` | Custom fetch implementation (SSR, testing) |

### `GraphQLErrors`

Error class thrown when the server returns GraphQL errors. Extends `Error` with an `errors` property containing the error objects and a `data` property holding any partial data the server sent with them.

### `GraphQLHTTPError`

Error class thrown when the HTTP response is not a GraphQL response: a body that is not JSON, or a non-2xx response with neither `data` nor `errors`. Carries `status` and the full response `body`.

### `FieldSelection`

Tracks selected fields in a GraphQL selection set. Used internally by generated SDK builders.

```typescript
const sel = new FieldSelection();
sel.addField("id");
sel.addField("name");

const nested = new FieldSelection();
nested.addField("city");
sel.addChild("address", nested);

sel.build();
// id
// name
// address {
//   city
// }
```

### `BaseBuilder`

Base class for generated query/mutation builders. Handles argument storage, field selection, query assembly, and execution.

```typescript
// Generated SDK code extends BaseBuilder:
class GetUserBuilder extends BaseBuilder {
  constructor(client: GraphQLClient) {
    super(client, "query", "GetUser", "user");
  }
  id(value: string) { this.setArg("id", value, "ID!"); return this; }
  async exec() { return (await this.executeRaw()).user; }
}
```

## Pitfalls

- **One client per identity on a server.** The client reads its options object on every request, so in server-side rendering a module-level client with a user's token is shared by every visitor. Build one per request there; in a browser app one client is right, and you can rotate the token by changing `options.authToken`.
- **No timeout by default.** Every call (`client.execute`, `client.rawQuery`, `batch`, and a generated builder's `.execute()`) takes `{ signal }`; use `AbortSignal.timeout(ms)` for a deadline, or wrap `fetch` in the client options for one deadline on every request. See [client: timeouts](https://github.com/ubgo/gqlkit/blob/main/docs/typescript/client.md#step-3--add-a-timeout-to-every-request).
- **`execute<T>` is a cast, not a check.** The type argument is your claim about the response; validate data from servers you do not control.
- **A batch fails as a whole.** One failing alias rejects the call with `GraphQLErrors`; read the resolved aliases from `err.data`.
- **Network failures are not wrapped.** A refused connection is the platform's own `TypeError`; only GraphQL and non-GraphQL HTTP responses become `GraphQLErrors` / `GraphQLHTTPError`.
